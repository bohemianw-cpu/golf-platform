# 골프 비서 유료 이용권·포인트 출시 준비

상태: **설계와 저장 구조 준비 완료 / 판매·포인트 지급 비활성** (2026-10-15)

## 1. 판매 방식

| 상품 | 사용 범위 | 가격 | 현재 상태 |
| --- | --- | --- | --- |
| 9홀 이용권 | 9홀 라운드 1회 | 미정 | 초안 |
| 12홀 이용권 | 12홀 라운드 1회 | 미정 | 초안 |
| 18홀 이용권 | 18홀 라운드 1회 | 미정 | 초안 |
| 월 구독 | 별도 검토 | 미정 | 미구현 |

- 이용권은 첫 유료 라운드 시작 때 해당 라운드 ID에 **한 번만** 연결한다. 같은 라운드의 샷 수정, 기록 재개, 완료 화면 재진입은 다시 차감하지 않는다.
- 홀 수를 늘리는 경우에는 다른 상품을 새로 산 것으로 자동 처리하지 않는다. 차액 결제와 변경 동의 화면을 별도로 설계한 뒤 지원한다.
- 초반에는 회당 이용권을 기본 판매 방식으로 권장한다. 구독은 반복 사용률과 가격을 관찰한 뒤 별도 동의와 해지 화면을 포함해 추가한다. 자동 갱신 동의는 가입 동의에 섞지 않는다.
- 가격을 정하기 전에는 `commerce_products`의 가격이 비어 있고 상태가 `draft`다. 앱의 구매 버튼 및 서버 결제 승인 API는 없다. 기존 스코어 기록을 잠그지 않는다.

## 2. 포인트와 보상

- 포인트는 **서비스 이용료 할인 전용**으로 설계한다. 현금 충전, 타인 양도, 외부 가맹점 사용, 현금 환급은 이 단계에서 제공하지 않는다. 경제적 권리가 달라지면 선불전자지급수단 해당 여부를 다시 검토한다.
- 친구 추천은 추천 코드 연결만으로 지급하지 않는다. 신규 가입자가 **처음으로 유효한 유료 이용권을 구매해 사용한 뒤**, 취소·환불·부정 이용 검토를 거쳐 양측에 각각 1회 지급하는 안을 권장한다. 초대된 회원 1명당 추천 1건만 허용한다.
- 트로피·배지의 화면상 획득은 금전적 포인트 지급과 분리한다. 보상 대상은 서버가 검증할 수 있는 좁은 사건(예: 첫 유효 라운드 완료)부터 시작한다. 화면에서 계산한 트로피를 그대로 지급 근거로 사용하지 않는다.
- 샷 입력의 서버 시각과 극최소 소요시간·사후 입력 구분은 [라운드 입력 신뢰도 기준](ROUND_INTEGRITY_POLICY.md)에 따른다. 시간 기준 통과만으로 포인트를 발급하지 않는다.
- 지급·사용·취소·만료는 `commerce_point_events`에 별개 사건으로 추가한다. `(user_id, event_key)` 고유 조건으로 같은 사건의 중복 지급을 막는다. 이용권과 주문 역시 주문/결제 고유 키를 갖는다.
- **지급액, 1인/월 상한, 최초 구매 판정 기간, 만료 기간, 취소 시 회수, 부정 이용 이의제기 절차는 판매 전에 확정하여 이벤트 화면에 고지한다.** 현재 포인트 지급·사용 기능은 활성화하지 않았다.
- 계정 중복 방지를 가입 단계에서 과도하게 강화하기보다, 금전성 보상 사건에 한정해 동일 결제 수단·취소 이력·비정상 반복 패턴을 검토한다. 휴대전화 인증이 필요해지면 그 목적과 보유 기간, 문자 비용을 별도로 고지하고 수집한다.

## 3. 주문과 결제 처리

1. 서버가 상품 가격과 회원의 사용 가능한 포인트를 조회하여 주문 금액을 계산한다. 브라우저가 보낸 가격이나 포인트 잔액을 신뢰하지 않는다.
2. 구매 화면에 상품 범위, 총액, 포인트 할인, 실제 결제액, 이용 개시 시점, 유효기간, 청약철회·환불 기준을 **결제 전** 표시한다.
3. 결제사에서 돌아온 주문번호·결제 금액을 서버가 저장한 주문과 비교하고, 서버에서 결제를 승인한다. 결제 키와 주문번호의 고유 조건으로 중복 승인을 막는다.
4. 결제 승인, 포인트 차감, 이용권 발급을 원자적으로 처리한다. 중간 실패 시 재시도해도 중복 발급하지 않도록 사건 키를 사용한다.
5. 환불 때 결제 승인 취소와 이용권 회수·포인트 복구를 하나의 이력으로 연결한다. 이미 시작한 이용권의 환불 가능 범위는 별도 법률 검토 후 약관과 화면에 명시한다. 단순히 '사용 시작 시 환불 불가'로 일괄 처리하지 않는다.
6. PG 웹훅은 서명/인증, 재전송, 순서 뒤바뀜을 처리해야 한다. 공개 브라우저 클라이언트에 PG 비밀 키나 Supabase service role 키를 두지 않는다.

## 4. 개인정보와 보존

- 계정 데이터와 주문 거래기록을 분리한다. 탈퇴 시 계정, 라운드, 이용권, 포인트, 추천 관계는 삭제된다. 주문 거래기록은 사용자 연결을 제거한 뒤 법정 보존이 필요한 최소 항목만 남긴다.
- 계약·청약철회, 대금결제·공급 거래기록은 관련 시행령의 **5년** 보존 기준을 따르도록 설계한다. `commerce_orders`에는 이메일·전화번호·샷 기록을 넣지 않았다. 계정 연결을 끊은 주문은 보존 기한에 매일 자동 정리한다. 분쟁으로 보존이 필요한 예외는 별도 운영 기록과 함께 `legal_hold`로 처리한다.
- 탈퇴 처리 감사기록 6개월과 거래기록 5년은 **다른 기록**이다. 개인정보 처리방침에 두 예외를 각각 설명해야 한다.
- 추천 보상 검증에 휴대전화나 기기 식별자를 수집하지 않는다. 필요성이 입증될 때에만 최소 항목, 목적, 보유기간, 수탁사 및 선택/필수 근거를 정한다.
- 운영명은 임시로 `골프 비서`, 문의는 `bohemianw@gmail.com`이다. 사업자 법적 명칭, 주소, 사업자등록/통신판매 정보, 개인정보 책임자 표기는 운영자가 확정해 제공한다.

## 5. 출시 직전 확정과 연결이 필요한 항목

1. 운영자/사업자 정보와 통신판매 관련 표기.
2. 9·12·18홀 가격, 부가세 포함 여부, 포인트 환산비와 최소 결제액.
3. 유료 이용권의 유효기간과 취소·환불 규정, 9→18홀 전환 규정.
4. 추천·트로피 보상의 금액, 횟수 제한, 지급 시점, 포인트 만료 및 취소 정책.
5. 결제사 계약, 테스트/실서비스 키, 결제 승인·취소·웹훅 연동.
6. 개인정보 처리방침과 유료 서비스 약관의 확정본 및 가입/구매 화면의 버전 관리.
7. 주문 분리 보관과 분쟁으로 보존 예외를 적용하는 운영 절차, 고객 안내문.
8. 서버에서 검증되는 보상·차감·이용권 사용 트랜잭션과 운영상 이상 거래 검토 도구.
